# 管理接口消费、状态与当前缺口

E02/E07的服务端contracts是权威；本仓库[快照](contracts/README.md)为只读消费输入。版本0.1.0包含37路径/39操作、17动作、44个schema；每个请求/响应的必需字段、类型和enum以快照为准。拆仓不增加或改变业务API。

## 调用约定

| 内容 | 前端行为 | 后端责任 |
|---|---|---|
| 身份 | 同管理来源cookie；不传伪造actor/role | 当前会话、MFA/step-up、角色与scope验证 |
| 查询 | environment/scope明确；默认50、最多200；opaque cursor | 分页、字段ACL、资源权限与信息泄漏控制 |
| 幂等 | 一个真实用户意图生成一个键；重试保留原键和参数 | 同键同摘要返回原结果，异摘要冲突 |
| CAS | 原样保留action响应ETag，批准/execute/cancel发送If-Match | 版本、当前政策、权限/证据竞争检查 |
| 金额 | 十进制整数字符串和币种/单位一起展示 | 订单可退值、币种、商户与分录守恒，拒绝溢出 |
| 错误 | 按code/retry_class处理，不仅看message | 拒绝类别稳定，不泄漏其他租户存在性或秘密 |
| 敏感读取 | SupportGrant绑定资源/字段，每次取回后审阅 | 到期/撤销/内容范围与访问审计，永不返回凭证明文 |

初版采用有界轮询，无须新增SSE/WebSocket：活跃action初始2秒，连续未变化后退避至10秒，后台页面暂停轮询；重新聚焦先查当前会话/状态，遵守Retry-After。429/临时读取失败允许有界退避，权限/输入错误不重试；创建或执行回执未知先按原action/业务键查询。

客户端超时不代表服务器未执行。CreateAction未取得ID且回执未知时，只能以原幂等键/同参数重试或走核对；不得先生成新键。审批/执行/取消参数发生变化是新意图，不能套用原批准。

## 页面状态

AdminAction：pending_approval→ready→executing→succeeded/failed/unknown，另有rejected/cancelled/expired。前端不得把ready渲染为“已完成”，也不能把unknown显示为“失败，可重新执行”。

使用服务端payload_digest和不可变request渲染审批预览；不由浏览器重新计算摘要作为权威。maker_checker要求申请人与至少一批准人不同，required_approvals=1是一个独立批准者。多角色同人不满足双人规则。

执行成功还要区分领域结果：退款pending/unknown保持可追踪；节点draining/quarantined不算idle；模型禁用阻止新使用，已发生费用不消失。复杂效果查询统一使用关联ID，不从页面文案推测。

## 39操作覆盖的界面入口

会话查询/注销、总览、用户/组织、Run/工作区、节点/模型、付款/退款、账本、对账/风险case、发行/开关、审计、管理动作及批准/执行/取消、SupportGrant列表和授权内容读取。所有类型化写仍通过AdminAction，不按页面新增任意管理HTTP操作。

## 尚未进入0.1.0的前置接口

| 缺口 | 影响 | 处理与阶段 |
|---|---|---|
| 登录开始/OIDC回调/step-up | 无法只凭session GET完成真实登录 | PREP-03由R3补服务端契约，W01真实验收前必须完成 |
| 平台principal/授权列表、撤销、授权有效期展示 | role_grant有动作，但不代表完整授权管理闭环 | PREP-04冻结查询/撤销语义；未补齐不显示假“完整管理员管理” |
| 新价格草稿创建/查询/校验 | pricing.publish只能引用已有price_version_id | PREP-04补版本生命周期；暂只展示已由受控流程创建的版本 |
| SupportGrant显式撤销与用户授权获取 | 现有列表/读取不构成完整授权流程 | PREP-04明确用户同意、撤权传播和后台入口，W05前关闭 |
| case分派/备注/关闭 | 现有风险/对账case只有查询 | 可先只读；写入功能需新契约，不能任意更改状态 |
| 异步审计/财务导出 | 现有分页接口没有导出作业 | 暂不承诺全量导出；明确批准、范围、过期/下载后再开放 |

这些是服务端与Admin共同准备项，未定义的接口不能用假路径、纯前端状态或粘贴任意ID绕过。扩展时先改服务端契约/权限/验收，再更新消费快照和客户端；本轮不擅自给0.1.0填入未评审API。
