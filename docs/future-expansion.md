# 后继阶段与扩展约束

管理后台随业务能力开放，不因为界面或仓库已建好就启用未验证的云端操作。E11保持一个前端工程；新后台服务需独立ADR，默认仍使用E07领域接口。

| 阶段 | 管理能力增量 | 接口/数据变化 | 放行要求 |
|---|---|---|---|
| 当前核心 | ADM-01～10，七角色、只读查询、17类动作、批准与审计 | AdminAction/Approval/Execution/SupportGrant | ADMIN-A01～10及启用领域真实证据 |
| G4 | 自动化/子Run/渠道元数据与受保护停新工作、扩展包撤销 | occurrence、parent/root、delegation、connector action和包版本显示；新增动作必须新schema | 不伪装用户批准，不重放unknown，不扩大子预算 |
| G5 | 企业IdP/SCIM、自定义角色/双审批、Objective、数据保留/私有部署状态 | 企业政策版本、同步tombstone、来源/派生链、目标根/周期和处理case | 真实企业试点与MG迁移；平台管理员不自动读租户私有内容 |
| G6 | 区域权威/接管、2/4卡资源组、容量/预热、平台评测与SDK兼容 | authority_epoch、group/成员代际、单写证据、预热预算、支持矩阵 | 无旧writer隔离不切主，无全成员清理不强放设备 |

## 新动作接入顺序

先明确领域状态与可逆性→服务端动作schema/权限/审批政策→目标版本/证据引用→持久派发与unknown核对→Admin表单/预览→负例/竞态/回退→发布能力开关。审批政策由服务端固定，前端不得从任意远端schema生成无审阅的通用命令控制台。

新权限使用独立permission，旧角色默认不自动取得新增敏感能力。角色模板或scope语义变化会使既有审批需重验；不得仅刷新前端菜单就视为完成权限迁移。

## 调整影响表

| 调整 | 必须同步 |
|---|---|
| Admin API字段/状态 | E02权威契约、E07校验/迁移、E11消费快照/页面、黄金载荷和兼容清单 |
| 角色/独立批准 | 服务端policy、IdP/授权、权限矩阵、step-up/撤权/自批负例 |
| 金额/退款/冲正 | 原领域不变量、Quote/账本/商户、用户说明、管理预览与对账 |
| 节点/资源组/区域恢复 | E07/E08授权/证据、旧版本拒绝、操作手册及故障演练 |
| UI/构建框架 | 会话/缓存/CSP、可访问性、浏览器矩阵和独立回退 |
| 支持内容/导出 | 用户授权、scope/期限/撤权、下载与审计政策，禁止新增凭证可读范围 |

管理员行为不能成为模型训练或评测的真实敏感数据源。未来辅助运营Agent最多生成提案/解释，不能成为独立批准人或自行调用平台高风险动作。

原G4—G6目标和资源/迁移门槛继续适用；其真实设备、账号、地域经营与容量证据未在本项目文档阶段取得。
