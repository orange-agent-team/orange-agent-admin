# 审计与精确范围权限

此切片使用服务端本地候选提交23d5b89079171b9f6b3cd33e18099c0293caf6ba的Admin0.1.3契约；SHA与来源写入`docs/contracts/snapshot.json`。普通构建只校验本仓库固定快照，不读取相邻服务端未提交源码。服务端候选尚未合入正式主线，不能据此宣布完整Admin或生产发布完成。

新增审计列表、有限游标分页、事件详情、刷新和撤权清屏。界面按事件收录顺序展示；回到最新页会重新读取当前边界。旧记录的请求标识缺失时显示“未记录”，不使用事件编号伪造追踪。已记录事件不代表对应任务、付款或设备回收已经完成。界面不提供一致性导出。

旧AdminSession.permissions是跨范围权限的交集，可能遗漏某个范围特有的权限。新`GET /admin/v1/session/permissions`返回当前主体在所选范围的有效权限，绑定主体、scope及policy_version。导航和操作控件使用此精确集合；切换范围时先清空旧查询和详情，等待新权限返回。范围权限接口缺失或出错时显示不可用，不以不完整的旧汇总替代。

审计列表/详情继续验证环境、范围和目标ID，拒绝未知危险字段以及非recorded的结果解释。权限错误使会话重新核对并清除数据；游标失效清空旧页，可通过刷新重新浏览。元数据只留在当前内存查询实例，不持久化到浏览器存储。原有管理动作的幂等、预览摘要、ETag、独立批准与unknown处理保持原约束。

已执行的证据分层：15项客户端测试、TypeScript和生产模式构建、8项Chrome接口替身用例；独立服务端还通过真实Chrome/HTTPS/API/PostgreSQL联调，覆盖分页、空追踪、跨范围拒绝与实际撤权后的清屏。增强用例在全局角色、权限交集和可见范围都不变时撤销当前范围的审计权，另一个范围仍保留审计权。真实联调会话为明确数据库夹具，不等于新MFA签发认证；集成后的实际Keycloak登录与双人批准回归仍须另行执行。

运行`node scripts/check.mjs --browser`进行客户端/构建/接口替身浏览器验收。实际API联调由服务端`check-admin-audit.py --admin-repo PATH --node PATH`明确选择本目录，使用自己的临时数据库和本机测试TLS，不更新系统信任、不访问真实用户数据、不产生真实资金或公开发布。
