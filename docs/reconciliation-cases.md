# 对账事项

在管理后台选择具有对账查看权限的平台或租户范围，进入“对账事项”查看当前状态、业务引用、经办人和下次核对时间。列表以登记顺序分页，查询和详情读取会写入审计。切换范围或撤回权限后，界面清除先前的详情。

财务管理员可在详情中申请分派或追加备注。申请需要关联工单和原因，并绑定当时看到的事项版本。提交后可以复制操作编号，获取审批预览并执行。经办人在执行分派时必须具备目标范围内有效的办理权限。

关闭事项需要提供凭据标识。申请人把操作编号交给另一位具有关闭审批权的财务管理员。复核人通过“管理操作”按编号读取最新预览、填写原因并批准。执行时服务端再次验证申请人和复核人的当前权限、事项版本与批准摘要。关闭更新事项状态和变更记录，交易与余额仍由财务服务负责。

重复提交相同操作使用原幂等键查询结果。遇到版本冲突时刷新详情，核对期间发生的变更，然后重新申请。历史记录按提交版本展示，可翻页查看。

## 测试商户现金日报

选择平台范围进入“测试商户对账”，可按 UTC 日期打开封存报告。每种结算币种的毛额、手续费和净额使用该币种的最小单位。本地购买和退款按原币展示，平台积分使用微积分。追加执行次数和发布对象逻辑字节秒分别衡量重试及对象占用；对账页面目前没有基础设施账单数据。

差异表列出业务编号和已知归属。平台财务可查看逐次观测，租户财务可从本账户的对账事项打开凭证。后续发现同一业务差异时会追加观测。页面使用独立 Admin 会话，并要求当前范围同时具有 payments.read、ledger.read、cases.read 三项权限。全部日报查询均经过审计。原始购买、任务扣费或退款需经相应业务流程处理。

在本仓运行 `node scripts/check.mjs` 验证已固定的契约副本和静态构建。跨仓浏览器验收从服务端运行 `python3 scripts/check-merchant-statements.py --admin-repo ../orange-agent-admin`，使用本机开发身份和可销毁测试库。[固定服务端契约](contracts/snapshot.json)
