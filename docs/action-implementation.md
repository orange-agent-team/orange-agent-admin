# 节点操作前端实施范围

2026-11-05。E11 使用本仓库固定的 0.1.2 契约快照，没有构建期相邻源码依赖或新增 npm 依赖。

管理操作页提供节点状态查询、排空/隔离/恢复申请。申请必须带实际查询得到的目标版本、工单和原因。详情先读取新的服务端投影和 ETag，展示完整请求、内容摘要、政策版本、到期时间和批准记录，再允许按当前会话权限批准、拒绝、撤回或执行。申请人不显示自批按钮；后端同样强制拒绝自批。普通用户角色不能因此获得平台权限。

写请求携带 CSRF、稳定幂等键及原 If-Match，不自动重试。连接失败或无法确认响应时冻结当前表单，仅提供“核对原请求”，沿用相同内容和请求键。版本冲突要求重新读取内容；重新验证身份走后端 step-up，完成登录后不自动继续旧操作。当前待确认请求只在页面内存中保留，跨页面关闭后的完整操作恢复工作台仍待补充；用户可用已知原操作编号查询，不应重新创建相同请求。

排空/隔离返回 executing 时明确显示“等待 Worker 确认”，不会显示设备已经回收。恢复可以申请和独立批准，但设备证据校验尚未完成，页面不提供执行按钮。其他动作仍是只读记录。region/resource 范围可以查看精确范围的动作，不能通过聚合总览取得平台数据。

验证方式：`node scripts/check.mjs --browser` 包含严格类型、固定契约、生产构建、11项客户端测试和5项显式 API 替身 Chrome 流程。真实身份/数据库由服务端 `scripts/check-admin-identity.py --admin-repo <本仓库>` 验证，包括真实 MFA 的节点申请 UI，以及两个真实登录主体的独立批准 API。两个身份审批的页面操作覆盖仍需扩展，不能把 API 流程称为完整审批 UI 认证。

所有结果以执行台账日志为准。完整 Admin、其余十四类写操作、资金/支持访问、真实 Worker 设备效果、企业及生产身份认证仍未完成。
