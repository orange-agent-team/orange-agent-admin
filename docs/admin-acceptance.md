## 十组必须用例

| ID | 场景 | 必须结果 |
|---|---|---|
| ADMIN-A01 | 普通用户cookie、组织owner、伪造前端role访问Admin API | 服务端拒绝；独立来源/会话不混用 |
| ADMIN-A02 | 无CSRF、错误Origin、过期MFA、管理员被撤权 | 写操作效果0次；敏感返回再次鉴权 |
| ADMIN-A03 | 同人兼任多个角色，申请后自行批准 | 拒绝；同主体不能构成双人 |
| ADMIN-A04 | 批准后改参数/target版本、批准过期、审批人离职 | 拒绝执行或新建请求，不沿用旧批准 |
| ADMIN-A05 | 重复execute、成功后响应丢失、后台崩溃 | 查询同一action/领域业务键，效果不重复 |
| ADMIN-A06 | 退款unknown、旧订单商户不匹配、冲正重复 | 保持核对，不新退款/双分录、不改原流水 |
| ADMIN-A07 | 节点排空但GPU未释放、恢复无健康证据 | 保持draining/quarantined，不强制idle |
| ADMIN-A08 | 私有内容查询、到期/撤回SupportGrant、诊断导出 | 默认只元数据，授权范围外拒绝，日志无秘密 |
| ADMIN-A09 | 管理页缓存/浏览器后退/账号切换/静态资源回退 | 无前用户敏感数据残留；服务端状态不回滚 |
| ADMIN-A10 | 紧急关开关、未签名发布物、未来区域接管调用 | 可有界止损；恢复须证据/批准，未准入能力拒绝 |

每个用例记录前端/服务端版本、角色/范围、action及业务ID、预期/实际、审计与效果次数。浏览器测试不能替代真实数据库、支付与设备试验；当前只存在用例定义，没有通过报告。

Admin Panel首发必须与用户控制台/完整Web Agent区分支持单元。G5企业和G6区域/组能力复用审批基础，但每种新动作仍需独立契约、权限和恢复证据。

## 独立仓库补充检查

在没有相邻Web源码路径的干净检出环境构建；契约快照与批准的服务端版本摘要一致；旧会话/旧包/旧审批及新后端字段组合有兼容或拒绝证据。列表/详情必须覆盖scope切换、迟到响应、空/分页/大输入、键盘/焦点及无障碍错误反馈。

登录/step-up与其他0.1.0未覆盖接口须先关闭PREP-03/04；若暂未实现导出或case编辑，界面明确没有该能力，不能使用生产假数据/本地状态记为通过。真实用例报告保存环境、构建/协议/数据摘要、主体/范围、效果次数/金额/设备状态、PASS/FAIL/MOCK_PASS/NOT_RUN与独立复核人。
