日期：2026-11-04。用户已要求纳入计划。范围为平台运营后台，独立于组织管理页面；设计基线明确，实际接口/身份/页面均未实现。

## 七种平台角色

| 角色 | 默认职责 | 明确不拥有 |
|---|---|---|
| platform_admin | 管理员授权申请、平台配置元数据与审批协调 | 不自动获得账务冲正、内容读取或签名私钥 |
| support_operator | 用户/任务元数据、支持case、单任务取消申请 | 私有内容默认不可见；不能改角色或资金 |
| compute_operator | 节点/模型、排空/隔离、模型变更申请 | 无账务/管理员授权权限 |
| finance_operator | 账单/分录/对账、退款和冲正申请 | 无工具执行、用户内容或任意余额写入 |
| security_operator | 风险case、凭证撤销、账号限制、隐私访问审阅 | 不默认读取秘密或直接改财务流水 |
| release_operator | 已签名发行物、灰度/撤回、运行开关 | 不持包签名私钥、不更改租户内容 |
| auditor | 已授权范围的只读审计/变更/资金元数据 | 无执行、批准或隐式内容访问 |

角色是平台权限模板，授权还带environment、region、tenant/resource scope、有效期；多角色组合不免除职责分离。组织owner/admin与这些角色互不继承。管理员初始配置通过受控身份部署完成，产品无默认账号密码。

## 动作等级

普通读取只需当前权限；个别记录仍须字段级过滤。单任务取消、节点排空、模型下架、撤销凭证和关闭新操作属于有界止损，可由相应权限人员完成，但要求原因、工单及审计。

下列动作要求两名不同实际主体的申请/批准，并在执行时再次核验权限、版本和证据：平台角色授予、节点恢复接单、模型启用、价格发布、管理员退款、账务冲正、扩大生产灰度、重新开启受影响功能、用户内容访问授权。角色组合、机器人或模型不能满足“不同人”的要求。

止损可以立即关闭新操作，但恢复不能沿用紧急例外。各动作在服务端固定policy，不接受浏览器传`skip_approval`、`approved=true`或任意风险等级。

## 审批与执行交互

填写目标/业务参数/工单→服务端生成不可变动作与摘要/审批政策→展示精确影响及版本→不同主体批准或拒绝→执行前重新检查当前角色/资源版本/证据→领域命令→显示执行中、成功、失败或unknown。

“批准”不等于“执行成功”，“退款confirmed”不等于外部到账保证，“取消请求”不等于资源已释放。审批内容一经修改必须创建新动作；旧批准不得继承。过期/撤权/目标状态变化阻止执行，正在执行的不可逆效果只可核对。

## 内容与凭证访问

管理员默认查询Run/Job的ID、owner标识、状态、时间、费用与脱敏错误。提示词、文件正文、工具输出、记忆等须用户明确授权的SupportGrant和独立批准，绑定资源、目的、读权限与到期。仅限读取该授权范围，不赋予工具执行或凭证读取。

凭证明文、支付密钥、签名私钥不通过Admin API返回，即使有内容授权也不例外。SupportGrant访问/下载逐次审计，撤权立即禁止新读取；已下载副本不可声称可强制收回。

## 工程与阶段

前端由独立orange-agent-admin仓库的E11负责，E07提供AdminSession、AdminAction、审批、审计及领域适配；E02维护契约。与原CP-006/SEC/OPS/PAY关联，但页面、管理会话和审批增量单独估算，不视作已被CP-006的旧3人日覆盖。

先交付身份/只读查询/审计，再做有界止损，然后开放经验证的双人批准操作；企业、多区域、多GPU动作随各自G5/G6门槛启用。现为桌面、服务端、用户Web、Admin四仓库；E11只拆前端维护边界，不另建独立账本。
